# Log Intrusion Detector

![CI](https://github.com/kaseeme1/log-intrusion-detector/actions/workflows/ci.yml/badge.svg)

A Python tool that reads Linux SSH authentication logs (`/var/log/auth.log`) and flags attacks the way a security operations (SOC) analyst would: brute-force attempts, password spraying, and the scariest one, a successful login right after a wave of failures.

> **Status:** in progress. Parser and detection rules are being implemented; the test suite defines the expected behavior.

## What it detects

| Rule | Severity | What it means |
|---|---|---|
| `success_after_failures` | **CRITICAL** | An IP failed 5+ times in 10 minutes, then **got in**. Possible compromised account. |
| `brute_force` | HIGH | One IP failed to log in 5+ times within 10 minutes. |
| `password_spray` | HIGH | One IP tried 5+ **different** usernames within 10 minutes (one password, many accounts, to dodge lockouts). |

Each rule produces at most one alert per IP, describing the worst burst of activity, so one noisy attacker doesn't bury everything else.

## Quick start

```bash
# run it on the included sample log
python -m detector sample_logs/auth.log

# also save machine-readable results
python -m detector sample_logs/auth.log --json report.json

# use in scripts or pipelines: exit code 2 if anything CRITICAL is found
python -m detector /var/log/auth.log --fail-on-critical
```

No third-party packages are needed to run it, just Python 3.10+.

### With Docker

```bash
docker build -t log-intrusion-detector .
docker run --rm log-intrusion-detector

# scan your own log file
docker run --rm -v /var/log/auth.log:/data/auth.log:ro log-intrusion-detector /data/auth.log
```

The container runs as a non-root user, and the log is mounted read-only.

## Sample data

`sample_logs/auth.log` is generated by `scripts/generate_sample_log.py` and has known attacks hidden in a normal day of traffic:

| Source IP | Scenario | Should alert? |
|---|---|---|
| `203.0.113.45` | 40 failed root/admin logins in ~3 minutes | brute_force |
| `192.0.2.77` | 12 different usernames, one try each | password_spray + brute_force |
| `203.0.113.99` | 7 failures on `deploy`, then a successful login and a suspicious `wget` | **success_after_failures** + brute_force |
| `198.51.100.200` | 6 failures spaced 15 minutes apart ("low and slow") | no (outside the window) |
| other `198.51.100.x` | normal users, the occasional typo, cron and sudo noise | no |

All IPs are from ranges reserved for documentation (RFC 5737), so none belong to real people.

## How it works

```
auth.log ──► parser.py ──► LoginEvent list ──► rules.py ──► Alert list ──► report.py ──► terminal / JSON
```

1. **Parse** (`detector/parser.py`): a regular expression pulls the timestamp, username, source IP, and success/failure out of each `sshd` line. Everything else (cron, sudo, session messages) is ignored.
2. **Detect** (`detector/rules.py`): events are grouped by IP, and a sliding time window counts failures (or distinct usernames) to find bursts.
3. **Report** (`detector/report.py`): prints a summary, top failing IPs, and alerts sorted by severity; optionally writes JSON for other tools (a SIEM, a dashboard, a ticketing system).

## Development

```bash
pip install pytest
pytest -v
```

GitHub Actions runs the test suite on Python 3.10, 3.12, and 3.13 on every push, then builds the Docker image and runs a smoke test that fails the build if the detector **doesn't** catch the hidden break-in.

Regenerate the sample log:

```bash
python scripts/generate_sample_log.py --seed 42
```
